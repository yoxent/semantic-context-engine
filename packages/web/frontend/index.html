What do search modes mean?
🔤 Keyword · Exact terms
Finds chunks whose text, file path, or heading contains your query words. Fast and predictable when you know the terminology (API names, package names, error strings).
Ranking: Matches start equal, then boost filename > heading > body text matches. Up to 2 hits per file.
Try: Unity Addressables, D1 binding
🧠 Semantic · By meaning
Embeds your question and ranks docs by conceptual similarity — not just shared keywords. Good for natural-language questions when docs mention related ideas in different words.
Ranking: Cosine similarity (0–1) on embedding closeness, plus the same filename/heading boosts. Up to 2 hits per file.
Try: how do flocks move without a leader
⚡ Hybrid · Recommended
Runs keyword and semantic, then merges both ranked lists. You get exact-term hits plus meaning-based matches in one result set — best default for exploratory search.
Ranking: Reciprocal Rank Fusion — top ranks from both lists add together; docs strong in both rise highest. Up to 2 hits per file.
Try: React form validation patterns

How ranking works

Every mode applies the same tie-breakers after its primary score. Higher scores appear first.

  1. Primary score
    • Keyword — all query words must match (AND). Base score 1.0 for every match.
    • Semantic — cosine similarity between your query embedding and each candidate chunk.
    • Hybrid — RRF fusion: each result earns 1 ÷ (60 + rank) from the keyword list and again from the semantic list; scores are summed.
  2. Relevance boosts (keyword & semantic)
    • Filename match — strongest (+ up to 8)
    • Heading match — next (+ up to 7)
    • Exact phrase or all terms in snippet (+ up to 4)
    • Longer, structured chunks get a small bonus (+1–2)
  3. Diversity — at most 2 results per file so one document does not dominate the page.
